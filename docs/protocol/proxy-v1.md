# P2X proxy-open protocol v1

`/p2x/proxy/1` is an exact-connection product substream protocol. Product clients expose outbound opening only; product servers expose inbound opening only. The probe protocol `/p2x/spike/1` is not part of this surface.

## Framing

The opened stream carries a four-byte big-endian `u32` frame length followed by exactly one canonical frame. `MAX_PROXY_HANDSHAKE_FRAME` is 4,096 bytes. Empty, oversized, truncated, trailing, unsupported-version, unknown ingress/mode/error, and malformed canonical IDs are rejected. Strings use `u16` byte lengths and fixed integers are big-endian. Phase 4 flushes Open/Accepted frames without closing the write half; opaque application bytes follow Accepted on the same stream.

Open version 1/discriminant 0 contains a request ID, bounded `RawTicket`, opaque upstream ID, nonzero registration revision, and closed ingress kind (`FixedTcp`, `HttpHost`, or `TlsSni`). The duplicated upstream and revision values are untrusted hints and must equal verified ticket claims and current server state.

The server response is legacy `Authorized` (discriminant 0, never a Phase 4 success), `Accepted` (discriminant 1, request ID, stream ID, `Tcp` mode), or `Rejected` (discriminant 2, optional request ID, stable public error). `Accepted` is emitted only after the immutable server-local upstream connects. Byte-exact non-production Open/Authorized/Accepted/Rejected vectors are committed in [`crates/p2x-protocol/testdata/proxy-v1.json`](../../crates/p2x-protocol/testdata/proxy-v1.json), and protocol tests reject trailing data and unknown discriminants. The framed proxy reader is exercised by the bounded `proxy_frame_decode` fuzz target.

## Authorization

The server worker reads exactly one flushed Open frame without requiring write-half closure; it does not consume or forward application data before admission and Accepted. It performs immutable ticket envelope/signature/time verification using the configured verification ring. The single server owner receives a validated candidate, rechecks current auth/session, tenant, enabled service, registration revision/expiry, authorization revision, and availability, then allocates the stream ID and consumes the ticket ID in one owner transition. Stream-ID randomness failure leaves replay state untouched. A consumed ticket stays consumed after write failure, cancellation, connection loss, or shutdown. A same-process owner-pipeline test passes a ticket issued by the real exchange Resolver/Registry through verification, live admission, allocation, and replay rejection.

The server verifies issuer, transport client, local server, tenant, service/upstream, selector fingerprint, registration revision and expiry, server authorization revision, active verification key, permission, time skew, and one-use limit. Replay cache capacity defaults to 8,192 and retains entries through ticket expiry plus the five-second clock skew; live entries are never evicted to make a replay valid again. Replay is `auth.ticket_replayed`. Unit and process tests cover the complete binding matrix, binding failure without replay consumption, expiry-plus-skew retention, replay rejection, exact N/N+1 proxy limits, persisted-identity restart recovery, and graceful worker drain. Configured proxy worker/replay limits are validated against 2,048 workers, 256 workers per client, 65,536 replay entries, and 30 seconds skew.

A client must advertise `Capabilities::PROXY_STREAM_V1` and require the same bit in the exchange intersection; mixed Plan 05/06 peers fail closed with `protocol.capability_mismatch` rather than waiting for EOF. The product client reads exactly one Open response under its original setup deadline, rejects legacy Authorized, mismatched correlation, and wrong mode, and starts opaque bytes only after Accepted. The server reserves stream/dial/service capacity before consuming the one-use ticket, dials only its immutable configured IP-literal `SocketAddr`, then emits Accepted. Pre-Accept setup, owner decisions, dialing, and response writes share one cancellable five-second worker deadline. Pre-Accepted failures use `upstream.connect_timeout`, `upstream.connect_failed`, or a bounded rejection; post-Accepted idle uses `upstream.idle_timeout`. There is no transparent retry after Accepted.

Every client open is sent on the selected libp2p `ConnectionId`. Existing confirmed direct connections win; otherwise a validated relay is prepared, DCUtR may establish a direct connection within the shared setup budget, and relay is selected after direct preference expires or fails. A guarded direct-open control enters the same pre-handshake failure path and proves one exact relay fallback. Once Open bytes may have reached a server, retry requires a fresh resolve and ticket. No raw ticket, selector, private target, or session value is logged.

The complete binding mutation matrix, low proxy-limit saturation, restart recovery, and graceful-drain process cases are locally certified by the canonical runner with correlated process evidence. Only deployment/platform checks remain outside the local gate.
